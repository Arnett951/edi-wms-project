# Snowflake lab

The same WMS lab tables (warehouse, item, location, inventory, lot attribute) loaded into a Snowflake
trial account, so the inventory-aging data exists in a third platform after Db2 (`bip-report/`) and
Azure SQL / Power BI (`powerbi/`).

```
Db2 TIREWMS.WMS --(powerbi/copy_db2_to_azuresql.py)--> Azure SQL wmslab
   --(snowflake/copy_azuresql_to_snowflake.py: CSV -> PUT @LOAD_STAGE -> COPY INTO)--> WMSLAB.RAW
   --> WMSLAB.ANALYTICS.VW_INVENTORY_AGING
```

## One-time setup

1. Snowsight worksheet, as ACCOUNTADMIN: run `sql/00_setup.sql` (warehouse, role, database).
2. `python snowflake/make_keypair.py` writes `~/.snowflake/wmslab_rsa_key.p8` and prints an
   `ALTER USER ... SET RSA_PUBLIC_KEY` statement. Run that in Snowsight. The script uses key-pair auth,
   so no password or MFA prompt is involved.
3. `pip install snowflake-connector-python`

## Load and reconcile

```
python snowflake/copy_azuresql_to_snowflake.py
```

Runs `sql/01_tables.sql` (idempotent), stages one CSV per table, reloads all tables in one transaction,
then compares row counts and SUM/MIN/MAX fingerprints, plus total inventory value, between Azure SQL and
Snowflake. A mismatch exits with code 2. Every run is logged in `WMSLAB.RAW.LOAD_LOG`.

Defaults: account `rrtrzrl-tj58203`, user `CARNETT909`, role `WMSLAB_LOADER`, warehouse `WMSLAB_WH`.
Override them with `SNOWFLAKE_ACCOUNT` / `_USER` / `_ROLE` / `_WAREHOUSE` / `_PRIVATE_KEY_PATH`.

## Snowpark notebook

`notebooks/wms_aging_snowpark.ipynb`, generated by `notebooks/build_notebook.py` (edit the builder, not
the .ipynb). It runs in Snowsight or locally with the same key pair. It:

1. Rebuilds the inventory-aging dataset with the Snowpark DataFrame API and prints the SQL that Snowpark generates.
2. Reconciles it against `VW_INVENTORY_AGING` with `EXCEPT` in both directions (0 / 0 rows).
3. Buckets value by warehouse age and saves the result to `WMSLAB.ANALYTICS.INVENTORY_AGING_BUCKETS`.
4. Registers a Python UDF (`DOT_TO_MFG_DATE`) that decodes the WWYY in a DOT code and checks every stored MFG_DATE.
5. Reads query history by `QUERY_TAG` to show what each step cost.

## Things worth knowing (support angle)

- **Query history includes the running query:** a `QUERY_HISTORY_BY_SESSION` query sees itself while it's
  still RUNNING, with a meaningless `total_elapsed_time` (it came back as about -1.8 billion seconds).
  Filter on `execution_status = 'SUCCESS'`.

- **COPY load metadata:** COPY INTO skips files it has already loaded in the last 64 days, *silently*.
  It reports them as skipped rather than raising an error. Every run here re-uses the same file names,
  so the script passes `FORCE = TRUE`. Without it, a second run "succeeds" and loads 0 rows.
- **Constraints aren't enforced:** Snowflake records PRIMARY KEY but doesn't enforce it, so a double load
  creates duplicates without any error. The reconcile step is what catches that.
- **IDs have gaps:** AUTOINCREMENT values aren't contiguous. The second LOAD_LOG row came back as
  LOAD_ID 101, not 2. Never use them as a row count or assume they're sequential.
- **Worksheet "Run" runs one statement:** in Workspaces, Ctrl+Enter runs only the statement under the cursor.
  The first setup attempt only registered the key, and the role didn't exist yet. Use Ctrl+Shift+Enter (Run All).
- **Credits:** WMSLAB_WH is X-Small with a 60s auto-suspend. Query history is filterable by
  `QUERY_TAG = 'wmslab-copy'` / `'wmslab-reconcile'`.
